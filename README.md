# 🗂️ Умный органайзер файлов

Автоматический скрипт для сортировки файлов по папкам в зависимости от их типа. Экономит время на ручную организацию загрузок и рабочих директорий.

## ✨ Возможности

- **Автоматическая сортировка**: Распределяет файлы по категориям (`images`, `documents`, `torrents` и др.).
- **Безопасный режим (`--dry-run`)**: Показывает, что будет сделано, без реального перемещения файлов.
- **Защита от дубликатов**: Три стратегии обработки:
  - `rename` — автоматически переименовывает (добавляет `_1`, `_2` и т.д.)
  - `skip` — пропускает файл при конфликте имён
  - `replace` — заменяет существующий файл, **сохраняя старый как `имя.bak-ГГГГММДД_ЧЧММСС`** (обратимо)
- **Отмена операций**: Ведётся журнал всех перемещений (`.organizer_undo.json` в формате JSONL), можно отменить последнее действие или несколько (`--undo`, `--undo-count`, `--undo-info`).
- **Безопасная отмена**: если на исходном месте уже есть новый файл пользователя, undo **не перезаписывает его**, а восстанавливает файл под свободным именем (`rename`), пропускает (`skip`) или заменяет (`replace`) — в соответствии с `duplicate_strategy`.
- **Полностью обратимая стратегия `replace`**: заменённый файл сохраняется как `*.bak-<timestamp>`, и полный `--undo` возвращает на место и его, и новый файл.
- **Пересортировка внутри категорий**: файл, лежащий не в своей папке (`videos/photo.jpg`), будет пересортирован в правильную категорию; файл в правильной папке не трогается.
- **Блокировка по папке**: одновременная сортировка *разных* папок работает параллельно; повторный вход в *ту же* папку из мониторинга пропускается.
- **Мониторинг**: Режим постоянного наблюдения за папкой с автоматической сортировкой новых файлов (`--monitor`). Реагирует на создание, переименование/перемещение в папку и дозапись файлов; не трогает ещё скачивающиеся файлы (проверка стабильности размера/mtime).
- **Игнорирование системных файлов**: Не трогает скрытые файлы и сам скрипт.
- **Статистика**: Выводит отчёт о количестве перемещённых файлов, дубликатов и удалённых пустых директорий.
- **Рекурсивная обработка**: Опциональная сортировка файлов во всех вложенных папках с очисткой пустых директорий.

## 🚀 Установка и использование

### Требования

- Python 3.9+
- Для GUI версии: библиотека `tkinter` (обычно встроена в Python, на Linux может потребоваться установка пакета `python3-tk`).
- Для режима мониторинга: опционально `watchdog` — при отсутствии автоматически используется polling-режим.

Установка (опционально, даёт команды `file-organizer` и `file-organizer-gui`):

```bash
pip install -e .            # ядро + CLI
pip install -e ".[watchdog]"  # + мгновенный мониторинг по событиям ФС
pip install -e ".[dev]"       # + pytest, ruff, mypy, coverage
```

Без установки скрипты запускаются напрямую из каталога проекта.

### Консольный запуск (`file_organizer.py`)

1. **Обычный режим** (файлы будут перемещены):
   ```bash
   python3 file_organizer.py /путь/к/папке
   ```
   *Если путь не указан, используется текущая директория.*

2. **Режим просмотра** (без изменений, только план):
   ```bash
   python3 file_organizer.py /путь/к/папке --dry-run
   ```

3. **Тихий режим** (минимум вывода):
   ```bash
   python3 file_organizer.py /путь/к/папке -q
   ```

4. **Без рекурсии** (только файлы в корне папки):
   ```bash
   python3 file_organizer.py /путь/к/папке --no-recursive
   ```

5. **Отмена последней операции**:
   ```bash
   python3 file_organizer.py /путь/к/папке --undo
   ```

6. **Отменить последние N перемещений** (`-1` = все):
   ```bash
   python3 file_organizer.py /путь/к/папке --undo-count 5
   ```

7. **Режим мониторинга** (постоянное наблюдение за новыми файлами):
   ```bash
   python3 file_organizer.py /путь/к/папке --monitor
   ```

8. **Информация о доступных отменах**:
   ```bash
   python3 file_organizer.py /путь/к/папке --undo-info
   ```

9. **Свой файл конфигурации** (вместо `config.json` рядом с модулем):
   ```bash
   python3 file_organizer.py /путь/к/папке --config /путь/к/my-config.json
   ```

Полный список опций: `python3 file_organizer.py --help`

### Графический интерфейс (`file_organizer_gui.py`)

```bash
python3 file_organizer_gui.py
```

**Возможности GUI:**
- **Выбор папки**: Кнопка для удобного выбора директории через проводник.
- **Рекурсивная обработка**: Опция для сортировки файлов во всех вложенных папках.
- **Тестовый режим**: Галочка для запуска без реального перемещения файлов.
- **Мониторинг**: наблюдение за папкой с учётом выбранных опций (рекурсия, dry-run).
- **Логирование**: Окно с подробным отчётом о действиях в реальном времени.
- **Очистка**: Автоматическое удаление пустых папок после перемещения файлов (при рекурсии).
- **Прогресс-бар**: Визуальное отображение прогресса обработки.
- **Счётчик отмен**: Сколько операций доступно для отмены (`--undo-info` в GUI).

### Примеры

Сортировка файлов в папке «Загрузки»:
```bash
python3 file_organizer.py ~/Downloads
```

Проверка того, что будет сделано в текущей папке:
```bash
python3 file_organizer.py --dry-run
```

Отменить последние 3 перемещения:
```bash
python3 file_organizer.py ~/Downloads --undo-count 3
```

Запустить мониторинг папки «Загрузки»:
```bash
python3 file_organizer.py ~/Downloads --monitor
```

## ⚙️ Как это работает

1. Скрипт сканирует файлы в указанной директории (`os.scandir`, stat берётся бесплатно);
   недоступные подпапки учитываются в статистике ошибок, а не игнорируются молча.
2. Определяет тип файла по расширению.
3. Проверяет безопасность путей и целевой папки категории.
4. Создаёт целевую папку (например, `images`), если она не существует.
5. Перемещает файл в целевую папку.
   - При конфликте имён применяется стратегия из конфига (`rename` / `skip` / `replace`).
   - При `replace` старый файл сохраняется как `имя.bak-<timestamp>`.
6. Все перемещения дописываются в журнал `.organizer_undo.json` (JSONL, append-only).
7. После завершения удаляются пустые папки (при рекурсивном режиме).
8. Выводится статистика по завершении.

## 🔄 Отмена операций

Журнал `.organizer_undo.json` лежит в корне отсортированной папки: одна JSON-запись на строку.
Журнал переживает перезапуск программы, устаревший формат (JSON-массив) читается автоматически.

Поведение `--undo-count N`:

| `N` | Результат |
|-----|-----------|
| `-1` | отменить все операции |
| `0` | ничего не делать (безопасный no-op, журнал не портится) |
| `> 0` | отменить последние `N` операций |
| `> количества операций` | отменить всё с предупреждением |
| `< -1` | некорректное значение — no-op с сообщением |

Если на исходном месте уже существует файл (пользователь создал новый), undo **не затирает его молча**: применяется `duplicate_strategy` из конфига. Неудавшиеся операции остаются в журнале для повторной попытки.

## 🛡️ Безопасность

- Скрипт **не удаляет файлы** при сортировке — только перемещает. Стратегия `replace` сохраняет заменяемый файл как резервную копию `*.bak-<timestamp>`.
  - Исключение: удаляются **пустые** папки при рекурсивной очистке (`clean_empty_dirs`).
- Игнорирует сам себя и скрытые файлы (начинающиеся с `.`).
- Игнорирует файлы-«маркеры» незавершённой загрузки (`.crdownload`, `.part`, `.partial`, `.download`, `.tmp`, `.filepart`) в режиме мониторинга.
- Режим `--dry-run` позволяет предварительно убедиться в корректности действий.
- **Защита от Path Traversal**: проверка, что все обрабатываемые пути находятся внутри рабочей директории (включая симлинки).
- **Защита целевой папки**: после создания папки категории проверяется её `resolve()` — симлинк-категория наружу или небезопасное имя категории не позволят увести файлы за пределы папки.
- **Валидация имён категорий**: имя категории обязано соответствовать `^[a-z0-9_-]+$`; `/`, `\`, `..` и абсолютные пути запрещены.
- **Атомарная запись журнала отмены**: перезапись через временный файл + `os.replace` + `fsync` — сбой питания/прерывание не оставит половинчатый журнал.
- **Последовательность undo/organize**: `undo_last_operation` и `organize_files` синхронизированы одним локом, параллельная работа не повреждает журнал.
- **Валидация путей**: запрет на использование `..`, абсолютных путей и symlink вне директории.
- **Защита системных директорий**: корень ФС (`/`), `/root`, `/home`, домашний каталог пользователя и системные директории (`/etc`, `/usr`, `/bin`, …) запрещены как рабочие папки.
- **Защита от DoS**: лимит итераций подбора имени (1000), лимит размера файла (1 GB по умолчанию, настраивается через `max_file_size`).
- **Маскировка путей** в логах для приватности: относительные пути внутри рабочей папки; имя каталога (или `~/…`), а не абсолютный путь.
- **Валидация конфига**: битый или невалидный `config.json` (включая JSON-массив, не-строковые расширения, невалидные стратегии) не роняет программу — используются настройки по умолчанию.

## ⚙️ Конфигурация

Файл `config.json` рядом с модулем:

```json
{
  "categories": {
    "images":    ["jpg", "png", "..."],
    "documents": ["pdf", "docx", "..."],
    "other":     []
  },
  "settings": {
    "dry_run":            false,
    "recursive":          true,
    "clean_empty_dirs":   true,
    "ignore_hidden":      true,
    "duplicate_strategy": "rename",
    "use_watchdog":       true
  }
}
```

Дополнительные настройки (можно добавить в `settings`):

| Ключ | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `dry_run` | bool | `false` | Только план, без перемещений |
| `recursive` | bool | `true` | Обрабатывать подпапки |
| `clean_empty_dirs` | bool | `true` | Удалять пустые папки после сортировки |
| `ignore_hidden` | bool | `true` | Игнорировать файлы с `.` в начале |
| `duplicate_strategy` | str | `"rename"` | `rename` \| `skip` \| `replace` |
| `use_watchdog` | bool | `true` | Использовать watchdog (если установлен); `false` = polling |
| `script_files` | list[str] | список служебных файлов | Имена файлов, которые не сортируются |
| `max_file_size` | int | `1073741824` | Лимит размера файла в байтах |

Невалидный или нечитаемый конфиг (в том числе JSON-массив вместо объекта)
не роняет программу: используются настройки по умолчанию с предупреждением в логе.
Файл `config.json` создаётся автоматически при первом запуске, если его нет.
